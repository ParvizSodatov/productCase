# ProductCase — контекст проекта

Этот файл — краткая память проекта. Читай его в начале каждой новой задачи.

## Идея

ProductCase — витрина IT-проектов Таджикистана, местный аналог Product Hunt.
Разработчики, студии и компании публикуют свои проекты, люди голосуют и комментируют,
лучшие попадают в топ дня и недели.

Название рабочее: ProductCase = product + case (кейс, реальный проект), на слух почти как showcase.

## Принятые решения

- **Тематика:** всё, что связано с IT и цифровизацией, а не только сайты.
- **Категории (11):** Веб, Мобильные приложения, Боты, ИИ-инструменты, Автоматизация,
  Для разработчиков, Дизайн, Обучение, Игры, Железо и IoT, Цифровые услуги.
  Один проект может быть в нескольких категориях (до 3). У категорий есть подкатегории.
- **Вакансий на сайте НЕ будет.**
- **Политики на сайте НЕ будет:** только IT-проекты, нужны правила площадки и модерация
  (удаление комментариев, жалобы, бан).
- **Профили двух типов:** личный (человек) и компании/команды.
  Входит всегда человек; он может создать страницу компании и пригласить коллег.
  Проект публикуется «от себя» или «от компании», на странице проекта видны владелец и создатели.
- **Вход:** через GitHub и Google, без паролей.
- **Голоса:** один аккаунт — один голос.
- **Языки:** русский и таджикский на старте, английский позже (окончательно не решено).
- **Монетизация (позже, когда будет трафик):** платное продвижение, спонсоры, премиум-аккаунт.
- **Старт:** до запуска собрать 30–50 проектов от друзей и знакомых IT-компаний.

## Стек (согласовано 2026-11-24)

Фронтенд выбран, бэкенд — нет.

- **Next.js 16 + React 19 + TypeScript.** Причина — сайт должен быть первым
  в поиске: Next отдаёт готовый HTML, поэтому работают индексация и превью
  ссылок в Telegram. Жалоба «Next медленный» относится к локальной разработке,
  а не к посетителю; для посетителя он быстрее обычного SPA.
- **Правило скорости:** публичные страницы (лендинг, топ, категории, проект)
  данные получают на сервере и собираются статикой. `'use client'` ставить
  только на интерактивные куски, иначе теряется весь смысл Next.
- **CSS-модули**, без Tailwind. Ноль лишних зависимостей, цвета в переменных
  в `app/globals.css`.
- **lucide-react** для иконок: в сборку попадают только использованные,
  примерно по 1 КБ. Логотипы GitHub и Google — SVG прямо в коде.
- **TanStack Query — позже**, когда возьмёмся за голоса, комментарии и
  подгрузку списков. Не как основа, а внутри интерактивных кусков.
- **zod** для проверки форм — обязательно, вместе с бэкендом.
- **Особенность Next 16:** в `next.config.ts` включены `cacheComponents`
  и `partialPrefetching`. Из-за них страница, читающая адрес (`params`),
  требует либо обёртки в `<Suspense>`, либо `export const instant = false`.
  У нас стоит второе — страницы собраны заранее целиком, делить их
  на каркас и содержимое незачем.
  `export const dynamicParams` с `cacheComponents` НЕ работает: сборка падает.
- **TanStack Start рассматривали и отклонили:** стабилен только с 13.10.2026,
  материалов и готовых рецептов под SEO мало. Вернуться к нему можно на
  следующем проекте.

## Структура папок

```
productCase/
  PROJECT.md     — этот файл
  frontend/      — Next.js, здесь вся работа сейчас
  backend/       — зарезервировано, пусто
```

Запуск фронта: `cd frontend` и `npm run dev`, затем http://localhost:3000

Готовые страницы (вёрстка по макетам, данные-заглушки в `frontend/lib/mock.ts`):
`/`, `/category/[slug]`, `/project/[slug]`, `/profile/[username]`, `/submit`,
`/login`, плюс 404, `robots.txt` и `sitemap.xml`.

Ещё не сделано: страницы `/rules`, `/about`, `/privacy` (на них есть ссылки
в подвале), настоящий логотип вместо «PC», таджикский язык.

## Как работать с Парвизом

- Отвечать на русском, комментарии в коде на русском, имена переменных и функций на английском.
- Стек: React + JS/TS на фронте, Node.js на бэке (бэкенд объяснять подробнее).
- Прямо указывать на ошибки и предупреждать о проблемах безопасности
  (XSS, хранение токенов, валидация данных и т.п.).
